# 8. CONCLUSION AND FUTURE WORK

## 8.1 Conclusion

NestQuest was built to address a well-documented inefficiency in the Indian property market: near-universal broker dependence that disadvantages owners and buyers alike. Existing portals — 99acres [13], Magicbricks [14], and NoBroker [12] — impose opaque pricing and broker-mediated fee structures. NestQuest proposes a brokerage-free marketplace where verified owners post listings at no cost, registered users enquire directly, and an AI-assisted price estimator counters information asymmetry.

The system is a full-stack web application using FastAPI [1] with Jinja2-rendered HTML, backed by MongoDB Atlas via the Motor async driver [9]. Authentication uses bcrypt-hashed passwords [6] and HS256-signed JWTs [7] in an httpOnly cookie. Property images are offloaded to Cloudinary [11], keeping the server stateless with respect to binary assets. The scikit-learn [2] Linear Regression model, trained on a synthetic dataset modelled on a public Kaggle housing dataset, returns a predicted price with a confidence range to guide — not replace — professional valuation.

A lifespan-driven startup sequence creates indexes idempotently, seeds administrator credentials, and optionally populates demonstration data. Pydantic v2 [16] schemas enforce input validation throughout the API layer, and a role-based dependency chain restricts listing approval, rejection, and featuring to verified administrators.

## 8.2 Objectives Achieved

All primary and secondary objectives have been met within the scope of the prototype.

Owner self-service posting was implemented via `/post` and `/edit/{id}`, collecting the full property schema (title, type, price, area, amenities, up to fifteen images) for admin moderation before public visibility. The status workflow `pending → active → sold/rented` models a realistic moderation lifecycle.

Buyer and tenant discovery is delivered through the `/properties` browse page with ten filter dimensions and five sort orders, backed by a full-text index over title, description, locality, and city.

Direct enquiry allows any registered or guest user to message an owner; the owner receives an optional email notification and can reply from their dashboard, with replies stored and visible to both parties.

The shortlist feature lets authenticated users toggle a saved flag on any property (a compound MongoDB index prevents duplicates). The AI price estimator at `/insights` accepts twelve inputs and returns a predicted price with a ± range based on RMSE ₹9,39,058. The admin dashboard surfaces platform statistics and allows per-listing status changes and per-user role management.

## 8.3 Major Contributions

**End-to-end brokerage elimination.** Free owner posting, admin-moderated visibility, and direct in-platform enquiry together remove every structural touchpoint at which a broker would traditionally extract a fee.

**Integrated AI price guidance.** Unlike existing portals that suppress pricing signals to preserve broker negotiation leverage [12][13][14], NestQuest surfaces an AI-generated fair-price estimate alongside every listing. Although the current estimator carries an R² of only 0.6538 [2][3], logging every prediction to a `predictions` collection creates a foundation for longitudinal model improvement as real transaction data accumulates.

**Async-first full-stack architecture.** FastAPI's ASGI runtime, Motor's non-blocking MongoDB driver, and Cloudinary's server-side upload API combine to handle concurrent browse, search, and image-upload requests without thread-pool exhaustion.

**Reproducible ML pipeline.** The Jupyter training notebook together with saved `model.pkl`, `columns.pkl`, and `metrics.json` artefacts provides a fully reproducible pathway from raw CSV to deployed inference endpoint. The custom CART implementation in `decision_tree.py` demonstrates regression tree construction from first principles, independently of compiled scikit-learn extensions [2].

## 8.4 Limitations

The most significant limitation is the synthetic training dataset. The 545-row Housing.csv was generated by `scripts/generate_dataset.py` using a fixed linear formula with Gaussian noise (NumPy seed 42), modelled on a public Kaggle dataset but not sourced from real transactions. Because the generative process is itself linear, the model achieves an artificially favourable fit (R²≈0.65); the same model trained on real heterogeneous market data would likely yield a lower R² and wider confidence intervals. Users must be clearly informed that the price estimate is a guide and not a professional valuation [3][15].

Several production-readiness security gaps also exist. MongoDB `$regex` search across user-supplied inputs is not escaped, creating a potential ReDoS vector [8]. No CSRF token is issued for state-changing form submissions. The JWT cookie is set with `secure=False` to accommodate local HTTP development; this must be changed to `secure=True` before any public deployment [7][8].

Admin list endpoints retrieve up to 500–1000 documents in a single query without server-side pagination, which will degrade performance at scale. Image content is not validated beyond MIME type and file size, so a file with an image MIME type but malicious content would not be detected before upload to Cloudinary [11].

## 8.5 Future Enhancements

**Input escaping and ReDoS mitigation.** Replace `$regex` queries with MongoDB Atlas Search (Lucene-backed) or sanitise inputs with `re.escape()` before compiling patterns [8], improving both query safety and full-text ranking.

**CSRF protection.** Add a double-submit cookie or synchronised token pattern to all state-changing form endpoints using a package such as `starlette-csrf`.

**HTTPS and secure cookies.** Deploy behind a TLS-terminating reverse proxy (Nginx or Caddy) with `secure=True` on the `nestquest_token` cookie and a cryptographically random `JWT_SECRET` of at least 256 bits [7][8].

**Real dataset and richer models.** Replace the synthetic dataset with verified Indian transaction data from property registrar open-data releases or licensed providers. Gradient Boosted Trees or ensemble regressors [3] trained on richer features (coordinates, age, floor, furnishing category) are expected to outperform Linear Regression and raise R² well above 0.6538.

**Map-based search.** Integrate a Leaflet.js or Mapbox tile layer backed by GeoJSON coordinates in the `properties` collection, allowing users to draw a geographic bounding box — a feature standard on mature portals [13][14].

**Push and in-app notifications.** Replace optional SMTP email with a WebSocket or Server-Sent Events channel for real-time browser alerts on new enquiries and admin status changes.

**Server-side pagination on browse.** The browse endpoint already supports `page` and `limit` parameters; implementing numbered pagination or infinite-scroll on the front-end would prevent large result sets from degrading client-side rendering.

**Rate limiting.** Add a Redis-backed rate limiter (via `slowapi`) to the authentication endpoints (`/api/auth/login`, `/api/auth/signup`) and the ML predict endpoint to protect against credential-stuffing and prediction abuse.

## 8.6 Final Remarks

NestQuest takes a meaningful step towards democratising property discovery in the Indian market. By eliminating the broker as a structural necessity — not merely reducing the fee — the platform restores pricing transparency and direct communication between owners and buyers or tenants. The AI price estimator, even trained on a synthetic dataset, establishes a precedent for evidence-based pricing within a self-service listing workflow [15].

The codebase was rebuilt from a single-purpose ML demo into a fully functional marketplace, validating that an async backend, server-rendered frontend, cloud-native storage, and reproducible ML pipeline can be assembled from open-source components at near-zero cost. The honest acknowledgement of the synthetic dataset, the modest R², and the outstanding security tasks charts a clear road map for the next development cycle. With the enhancements in Section 8.5 in place, NestQuest would be well-positioned for a public beta deployment across Indian cities.
